# Building the adjoint

The supported build is the `Dockerfile`, which produces the Debian package
described in the [README](../README.md). It runs the same `scripts/build.sh`
commands that are described here. Building outside Docker isn't supported, but
everything needed to do it is written down below, and a CI job
([`native-build.yaml`](../.github/workflows/native-build.yaml)) follows this
document literally, on a GitHub-hosted runner with no container. The commands
in the fenced blocks that follow a `<!-- ci:run -->` marker are the ones it runs.

## What you need

The adjoint is built against the libraries and `config.cmaq` of
[openmethane/CMAQ](https://github.com/openmethane/CMAQ), and nothing else is
taken from it. There are two ways to get them:

- **On Debian 13 (trixie)**, install the `openmethane-cmaq-dev` package from a
  [CMAQ release](https://github.com/openmethane/CMAQ/releases). Its `Depends:`
  brings the toolchain: `gfortran-14`, `build-essential`, `csh`, `m4`,
  `libnetcdff-dev` and `libmpich-dev`. The `Dockerfile` pins the version and
  checksum of the release it builds against (`CMAQ_VERSION` and
  `CMAQ_DEV_SHA256`).
- **On another system**, build them by following CMAQ's
  [docs/building.md](https://github.com/openmethane/CMAQ/blob/main/docs/building.md)
  at the version the `Dockerfile` pins, which gives the same files under
  `/opt/lib` and a `config.cmaq`. Set `CMAQ_CONFIG` to that `config.cmaq`.

To run the adjoint or its tests you also need `mpich` (for `mpirun`), and for the
tests `wget` and `ca-certificates`, which download the test data.

<!-- ci:run -->
```bash
sudo apt-get update
sudo apt-get install -y mpich wget ca-certificates
```

## Environment variables

| Variable | Default | Meaning |
| --- | --- | --- |
| `CMAQ_CONFIG` | `/opt/scripts/config.cmaq` | The `config.cmaq` to build with, which `openmethane-cmaq-dev` installs at the default. The build stops with a message if it doesn't exist |
| `ADJOINT_SRC` | `cmaq/` in this repository | The sources: the directory holding `CCTM` and `ICL`. They aren't merged with CMAQ's |
| `BIN_DIR` | unset | Where `ADJOINT_FWD` and `ADJOINT_BWD` are moved to. Set it to `/opt/cmaq/bin` to match the package and the tests |

`config.cmaq` reads more, with its own defaults: `M3LIB` (`/opt/lib`, where the
libraries are), `IOAPI_DIR` (`$M3LIB/ioapi_3.1`) and `M3HOME` (`/opt/cmaq`). Set
them if CMAQ's libraries aren't in the default places.

<!-- ci:run -->
```bash
export M3HOME=/opt/cmaq M3LIB=/opt/lib IOAPI_DIR=/opt/lib/ioapi_3.1 BIN_DIR=/opt/cmaq/bin
```

## The steps

Run from the root of this repository. `scripts/build.sh <binary>` runs the
`bldit` script for each binary:

| Step | Builds | Script |
| --- | --- | --- |
| `fwd` | `ADJOINT_FWD` | `scripts/bldit.adjoint.fwd.openmethane` |
| `bwd` | `ADJOINT_BWD` | `scripts/bldit.adjoint.bwd.openmethane` |
| `all` | both, in this order | |

<!-- ci:run -->
```bash
scripts/build.sh fwd
scripts/build.sh bwd
```

Then run the tests with `tests/test-run.sh`, which expects the binaries in
`/opt/cmaq/bin` (see [tests/README.md](../tests/README.md)).

The `bldit` scripts choose which source module is compiled for each part of the
model, so they are where to look before changing anything in `cmaq/CCTM`.

## Settings for a different system

All settings that depend on the system belong in `config.cmaq`, and this
repository adds none of its own:

- `myFC`, `myCC`: the compiler wrappers (`mpif90`, `mpicc`).
- `myFFLAGS`, `myCFLAGS`: compiler flags.
- `mpi`: the MPI library to link, `-lmpich` for MPICH and `-lmpi` for Open MPI.
  The `bldit` scripts link whatever it says.
- `NETCDF_LIB` and `NETCDF_MOD`: netCDF flags, taken from `nf-config`.

Everything that builds against the libraries must use the compiler version that
wrote their `.mod` files: `gfortran-14` for the libraries in
`openmethane-cmaq-dev`.

## What the build produces

| Path | In package |
| --- | --- |
| `$BIN_DIR/ADJOINT_FWD` | `openmethane-cmaq-adjoint` |
| `$BIN_DIR/ADJOINT_BWD` | `openmethane-cmaq-adjoint` |

The build also leaves `BLD_fwd_CH4only` and `BLD_bwd_CH4only` directories in
`scripts/`, which aren't packaged. A package contains the files at the paths
the build put them, with nothing moved, renamed or rewritten.

`scripts/build-deb.sh` makes the package, and its use is in the `Dockerfile`.
Its `Depends:` is generated by `dpkg-shlibdeps` over both binaries, plus `mpich`.

## Known limitations

- Only gfortran and MPICH have been tried.
- Only `amd64` is built in CI. The `aarch64` build that the old `make
  build-aarch64` made has not been tried against the package.
- The native build job runs on Ubuntu, with its own gfortran version, rather
  than on Debian 13. The package is only tested on Debian 13.
- The paths of the sources and the `BLD_*` directories are embedded in the
  binaries, so they differ with `ADJOINT_SRC` and with where the build runs.
  The machine code doesn't.
